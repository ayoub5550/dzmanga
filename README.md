# dzmanga

قارئ مانجا عربي، سريع وخفيف. يجمع **مصدرين مجانيين** للمانجا المترجمة للعربية:

| المصدر | الوصف | كيف نصل إليه |
|---|---|---|
| **مانجا العاشق (3asq)** | آلاف الأعمال بترجمة عربية أصلية من الفرق العربية (ون بيس 561 فصلاً مثلاً) | لا API رسمية — نقرأ الصفحات العامة ونحلّلها بـregex في `src/sources/asq.js` |
| **MangaDex** | ~735 عملاً له فصول عربية قابلة للقراءة | API رسمية مجانية بدون مفتاح |

مصادر جُرِّبت ورُفِضت: **Comick** (`api.comick.dev`) — يسرد آلاف العناوين بلغة
`ar` لكنها مجرد مرآة لبيانات MangaDex ولا يستضيف صور الفصول العربية
(`md_images: []` في كل ما اختبرناه، 2026-08-21) فلا فائدة منه للقراءة.

**الحالة: MVP** — بدون حسابات مستخدمين؛ تقدّم القراءة والمفضلة محفوظة محلياً على الجهاز (`localStorage`).

## البنية التقنية (عمداً بسيطة)

- Backend: Node.js + Express فقط (`src/server.js`) — لا قاعدة بيانات في الـMVP.
- Frontend: HTML/CSS/JS عادي بدون framework (`src/public/`), SPA بسيط بـ hash routing.
- المصادر: `src/sources/asq.js` (مانجا العاشق) + [MangaDex API](https://api.mangadex.org) — كلاهما مجاني بلا مفاتيح.
- صور الفصول تمر عبر `/img` (proxy في الباك-إند) لتفادي مشاكل CORS/hotlink وتفعيل caching.
- كل نداءات MangaDex تُخزَّن مؤقتاً في الذاكرة (`Map`, TTL=5 دقائق) لتخفيف الحمل والسرعة.

## التشغيل محلياً

```bash
npm install
PORT=3090 node src/server.js
```

## واجهات الـ API (كلها تُرجع JSON)

| Route | الوصف |
|---|---|
| `GET /api/home` | `{ hero, asq:{latest,popular,genres}, md:{...} }` — من المصدرين |
| `GET /api/browse?source=asq&order=latest&genre=&page=` | تصفّح مانجا العاشق |
| `GET /api/browse?source=md&page=` | تصفّح فهرس MangaDex العربي الكامل |
| `GET /api/search?q=` | بحث موحّد: `{ results, asq, md }` |
| `GET /api/manga/:id` | تفاصيل مانجا واحدة |
| `GET /api/manga/:id/chapters` | فصولها العربية القابلة للقراءة (pages > 0) |
| `GET /api/chapter/:id/pages` | روابط صور الصفحات (عبر `/img` proxy) |
| `GET /img?u=` | بروكسي صور MangaDex و3asq |

**المعرّفات:** عناصر MangaDex تحمل الـUUID كما هو، وعناصر العاشق تُسبَق بـ
`asq:` (مثال `asq:one-piece`)، والفصل `asq:<manga-slug>:<chapter-slug>`.

## نشر على VPS (يتبع نفس أسلوب باقي مشاريع صاحب الحساب)

- المسار: `/opt/dzmanga/`
- systemd unit: `dzmanga.service` مع `Environment=PORT=<داخلي>`
- nginx site يعمل proxy لبورت خارجي
- لا يوجد pm2، لا Docker (نفس القاعدة المتبعة في باقي التطبيقات على هذا الـVPS)

## قرارات تصميم مهمة (لتفهمها الوكلاء القادمون قبل التعديل)

1. **العربية فقط، بشكل متعمد** — ثابت `LANG = 'ar'` في `server.js` يُستخدم في كل
   نداءات MangaDex (`availableTranslatedLanguage[]=ar` للاكتشاف،
   `translatedLanguage[]=ar` لجلب الفصول). هذا اختيار المنتج (تطبيق عربي)، وليس
   قيداً تقنياً. لا توسّعه للغات أخرى دون التأكد من صاحب المنتج.
2. **الفصول ذات `pages: 0` تُستبعد** — هذه فصول "خارجية" (روابط لمواقع نشر
   رسمية/مرخّصة) لا يمكن لـMangaDex تقديم صورها. لذلك بعض العناوين المشهورة
   جداً (مثل الأعمال المرخّصة رسمياً) قد تظهر في "الأكثر شعبية" لكن بدون أي
   فصل قابل للقراءة — هذا سلوك طبيعي من MangaDex نفسه وليس خطأ.
3. **لا قاعدة بيانات بعد** — تقدّم القراءة/المفضلة غير محفوظة. القرار كان تعمّد
   إبقاء الـMVP بسيطاً. الخطوة التالية الطبيعية: `better-sqlite3` + معرّف جهاز
   بكوكي (بدون حسابات كاملة أول الأمر) لحفظ "آخر صفحة قرأتها" والمفضلة.
4. **بدون مفاتيح API** — MangaDex API مجاني بالكامل بدون تسجيل، لذلك لا أسرار
   للنشر في systemd.

## ملاحظة تجميلية معروفة (ليست خطأ)

بعض فرق الترجمة (scanlation groups) ترفع لـMangaDex غلافاً ترويجياً بديلاً
يقول "You can read this at: MangaDex" بدل غلاف العمل الحقيقي، حتى للمانجا
التي لها فصول عربية قابلة للقراءة فعلياً (تحققنا من هذا 2026-08-17: يظهر مع
عناوين تعمل فصولها بشكل طبيعي). هذا غلاف حقيقي قادم من MangaDex نفسه، وليس
خطأ فـ dzmanga. تحسين مستقبلي ممكن: اكتشاف هذا الغلاف تحديداً (عبر حجمه/بصمته)
واستبداله بغلاف احتياطي بدل عرضه.

## ما أُنجز في تحديث 2026-08-21

- مصدر ثانٍ: مانجا العاشق (`src/sources/asq.js`).
- واجهة على غرار تطبيقات المانجا العربية: شريط تنقّل سفلي، "تابع القراءة"،
  "مكتبتي" (مفضلة + سجل)، شارات آخر فصل/التقييم/المصدر على البطاقات، شريط تقدّم
  في القارئ، اختصارات لوحة المفاتيح، وتمييز الفصول المقروءة.
- حفظ التقدّم والمفضلة في `localStorage` (بدون حسابات ولا قاعدة بيانات).

## تحديث 2026-08-21 (جولة أداء + إصلاحات)

- **ضغط gzip** يدوي بـ`zlib` لكل ردود JSON/JS/CSS/HTML (بدون حزم): `/api/home`
  نزل من ~285KB إلى ~65KB.
- **كاش طلبات في الواجهة** (`getJson`) مع إلغاء تكرار الطلبات المتزامنة + دوال
  `prefetchJson` / `preloadImages`.
- **القارئ**: عدّاد صفحات حي، تحميل مسبق للفصل التالي بعد 55%، استئناف موضع
  القراءة داخل الفصل، نقر الحواف للتنقّل، إعادة محاولة الصور الفاشلة، رسالة
  واضحة عند فصل معطوب في المصدر (`broken` من الـAPI عبر فحص HEAD لأول صفحة).
- **إصلاح**: معرّفات فصول العاشق كانت تُرمَّز مرتين → فصل يفتح بلا صفحات.
  الآن `chapters()` تفكّ الترميز و`pages()` تقبل الشكلين.
- **إصلاح**: رقم الفصل يُستخرج أيضاً من داخل العنوان ("المذكرة 68") بدل "الفصل ؟".
- **وضع قراءة أفقي** (صفحة-صفحة بالسحب، `scroll-snap`) مع زر تبديل في رأس
  القارئ، والاختيار محفوظ في `localStorage` (`dz_mode_v1`). العدّاد في هذا
  الوضع يُحسب من `scrollLeft` (قيمة سالبة في RTL — استخدم `Math.abs`).
- `sw.js` (service worker) موجود لكنه لا يعمل على `http://` — يحتاج دومين + HTTPS.

## أفكار للتطوير القادم (لم تُنفَّذ بعد)

- مزامنة التقدّم بين الأجهزة (كوكي جهاز + SQLite) بدل `localStorage` فقط.
- فلترة أذكى لقائمة "الأكثر شعبية" لتفادي عرض عناوين بلا فصول عربية قابلة للقراءة
  (مثلاً استبعاد أي مانجا يعيدها `/api/manga/:id/chapters` بمصفوفة فارغة).
- PWA كامل: يحتاج HTTPS أولاً (`sw.js` جاهز).
- دعم "استكمال القراءة" في الصفحة الرئيسية.

## تحديث 2026-08-21 (مساءً): SEO + بنية تحتية للنشر العام

**على مستوى السيرفر (nginx — خارج هذا المستودع):**
- `gzip_proxied any` في `/etc/nginx/conf.d/00-perf.conf` (nginx افتراضياً لا
  يضغط الردود القادمة من proxy — كان `app.js` ينزل 44KB خاماً، الآن 12.6KB).
- `http2 on` + رؤوس أمان (HSTS/nosniff/Referrer-Policy) في site conf.
- `proxy_cache` باسم `dzimg` على `location /img` (2GB، أسبوع) — الصور المتكررة
  تُخدم من قرص nginx مباشرة بدون المرور على Node أو المصدر.
- بفضل HTTPS الآن: الـservice worker (`sw.js`) يعمل والتطبيق قابل للتثبيت PWA.

**داخل التطبيق (SEO — لأن الـSPA بروابط hash غير قابلة للفهرسة):**
- `GET /manga/:id` — رابط "جميل" قابل للفهرسة: يخدم `index.html` مع حقن
  `<title>`/description/OG/JSON-LD الحقيقية للمانجا بين علامتي
  `<!--SEO:START-->`/`<!--SEO:END-->` في `index.html`، وسكربت صغير يضبط
  `location.hash` ليفتح الزائر البشري صفحة المانجا في التطبيق.
- `GET /sitemap.xml` — يُبنى من `fullCatalog` + قوائم العاشق (كاش ساعة).
- `GET /robots.txt` — يسمح بالكل ويشير للـsitemap ويمنع `/api/` و`/img`.
- `PUBLIC_ORIGIN` قابل للتغيير عبر env عند تغيير الدومين.
- `loadMangaDetail(id)` دالة مشتركة بين `/api/manga/:id` و`/manga/:id`.
